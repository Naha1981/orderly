   480→  1479→  1479→Notes on this structure
   481→  1480→  1480→
   482→  1481→  1481→  - Every route handler's body is: authenticate → resolve tenant (or verify
   483→  1482→  1482→    super-admin, or verify webhook/cron secret) → validate → call a modules/*
   484→  1483→  1483→    function → respond. No exceptions found in the code reviewed — keep it that
   485→  1484→  1484→    way as new routes are added.
   486→  1485→  1485→  - modules/concierge/router.ts is the single dispatch point for every inbound
   487→  1486→  1486→    WhatsApp message. It is intentionally a plain, ordered function (plan.md
   488→  1487→  1487→    §10) — do not introduce a second routing mechanism elsewhere.
   489→  1488→  1488→  - modules/whatsapp/send.ts is the single outbound gateway. No module should
   490→  1489→  1489→    call the Evolution client directly for sending; only
   491→  1490→  1490→    lib/integrations/evolution/lifecycle.ts is called directly, and only from
   492→  1491→  1491→    tenant-connect and Super Admin flows.
   493→  1492→  1492→  - Two new modules recommended, not yet present: modules/recovery/ (Track C1)
   494→  1493→  1493→    and modules/delight/ (Track C3) — both are pure additions, no existing
   495→  1494→  1494→    module needs to change to accommodate them.
   496→  1495→  1495→  - The Restaurant Hub and its menu sub-page belong together (r/[slug]/ and
   497→  1496→  1496→    r/[slug]/menu/) but the menu page is the one visible gap in an otherwise
   498→  1497→  1497→    complete Hub.
