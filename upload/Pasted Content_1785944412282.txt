## `src/components/marketing/invite-form.tsx`

```tsx
'use client';

import { useState } from 'react';
import { Button } from '@/components/ui/button';
import { Input } from '@/components/ui/input';

export function InviteForm() {
  const [status, setStatus] = useState<'idle' | 'sending' | 'done' | 'error'>('idle');

  async function onSubmit(e: React.FormEvent<HTMLFormElement>) {
    e.preventDefault();
    setStatus('sending');
    try {
      const form = e.currentTarget;
      const res = await fetch('/api/v1/invite-requests', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
          restaurantName: new FormData(form).get('restaurantName'),
          ownerName: new FormData(form).get('ownerName'),
          phone: new FormData(form).get('phone'),
        }),
      });
      if (!res.ok) throw new Error();
      setStatus('done');
    } catch {
      setStatus('error');
    }
  }

  if (status === 'done') {
    return (
      <p className="mt-8 rounded-xl border border-[#e8722a]/30 bg-[#e8722a]/10 p-5 text-[#f0a04b]">
        Thanks! We&apos;ll WhatsApp you your personal invite shortly. Keep an eye on your phone.
      </p>
    );
  }

  return (
    <form onSubmit={onSubmit} className="mx-auto mt-9 flex max-w-md flex-col gap-3">
      <Input name="restaurantName" placeholder="Restaurant name" required className="h-12 border-white/10 bg-[#211a13]" />
      <Input name="ownerName" placeholder="Your name" required className="h-12 border-white/10 bg-[#211a13]" />
      <Input name="phone" type="tel" placeholder="Your WhatsApp number (e.g. 072 123 4567)" required className="h-12 border-white/10 bg-[#211a13]" />
      <Button type="submit" disabled={status === 'sending'} className="h-12 rounded-full bg-[#e8722a] text-base font-semibold hover:bg-[#f0823a]">
        {status === 'sending' ? 'Sending…' : 'Request my invite'}
      </Button>
      {status === 'error' && <p className="text-sm text-red-400">Something went wrong. Please try again.</p>}
    </form>
  );
}
```

## 1 · Executive Summary

**Orderly** is a WhatsApp-native restaurant growth platform for South African independent restaurants. It turns the messaging app every customer already has into a complete front-of-house engine: bookings, loyalty, AI concierge, marketing campaigns, customer recovery, reviews, operations, and plain-English intelligence.

**The core insight — the Empty Chair Principle:** an empty table earns R0. Not a little. Nothing. A sale that fills that seat, even at a discount, is money a restaurant would otherwise never see. Every feature in Orderly exists to fill empty chairs.

Orderly is **invite-only**, **founder-led**, and **pre-launch**. The restaurant owner gets their own branded WhatsApp connection; their customers never download anything.

**Rebrand note:** Orderly is the restaurant-focused evolution of the loyalty product previously specified as Flavourly OS. Loyalty is retained as one of ten engines (8 of 54 automations), not the whole product.

---

## 2 · Problem Statement

Independent restaurants leak revenue from six directions they can't see:

1. **Underutilised capacity** — empty tables on weekdays and off-peak hours.
2. **No-shows** — bookings that silently don't arrive.
3. **Silent churn** — regulars who quietly stop coming, unnoticed.
4. **Missed enquiries** — booking and catering requests unanswered during service.
5. **Reputation blind spots** — bad reviews seen days late.
6. **No attribution** — no idea which promotions actually worked.

Owners are **time-poor, non-technical, and thin-margin**. They will not adopt a CRM, configure dashboards, or ask customers to download an app. Any solution must meet them where they already live: **WhatsApp, in plain English, with no setup burden.**

---

## 3 · Target Market & ICP

**Primary ICP:** independent, sit-down restaurants in South Africa (1–3 locations), 15–80 covers, owner-operated, already using WhatsApp with customers.

**Expanded verticals (roadmap):** cafes, bars, bistros. The original six-vertical model (car washes, salons, barbers, retail) is deprioritised in favour of going deep on restaurants first.

**Why SA, why WhatsApp:**
- WhatsApp is near-universal; data costs make app downloads a real barrier.
- No-app, no-password, no-card removes every friction point.
- Invite-only, founder-led sales matches a trust-first market.

## 4 · Positioning

> **Orderly — Fill your empty chairs. Turn walk-ins into regulars.**

Orderly is **not** positioned as a loyalty programme. It is positioned as **the system that keeps a dining room full.** Loyalty is one mechanism among ten. The homepage, pricing, and pitch all sell the *outcome* (a full restaurant, fewer no-shows, regulars back, time reclaimed), with the 54 automations as the credibility underneath.

## 5 · Solution Overview

One platform, three surfaces:

1. **The Restaurant Hub** — one branded link per restaurant (`orderly.app/yourname`) + counter QR code. The universal entry from Instagram bio, Facebook, Google listing, website, and in-venue.
2. **The WhatsApp engine** — per-tenant Evolution API instance; guests chat with *their* restaurant. Keyword router + AI concierge.
3. **The owner dashboard** — bookings, guests, campaigns, reviews, insights, settings, billing.

## 8 · User Journeys

### Restaurant Owner
1. **Discovery** — sees Orderly (referral/founder outreach), lands on homepage, requests an invite.
2. **Invite** — Super Admin uploads them as a prospect, sends a WhatsApp invite with a branded claim link.
3. **Claim & onboard** — opens claim link, names the restaurant, connects their WhatsApp by scanning a QR (14-day trial starts).
4. **First value** — downloads their Smart Page link + counter QR; Orderly drafts their first "Fill Quiet Hours" campaign.
5. **Daily loop** — reads the morning brief; confirms bookings; taps one button to fill a slow night; sees redemptions land.
6. **Weekly loop** — Monday plain-English insights tell them what worked and what to do next.
7. **Expand** — upgrades tier to unlock bookings/concierge/reviews/operations as needs grow.
8. **Pay** — PayFast recurring billing; webhook confirms; trial converts to active.

### Customer (guest)
1. **Entry** — scans the counter QR, taps the Instagram-bio link, or texts the restaurant.
2. **Join** — texts `JOIN` or taps "Join Rewards" on the Hub → profile + 10 welcome points, no app.
3. **Engage** — texts `BOOK` to reserve, `BALANCE` to check points, asks the AI concierge questions.
4. **Redeem in-venue** — texts `REDEEM`, opens the GPS link at the restaurant, cashier scans the QR.
5. **Return** — receives birthday offers, win-backs, and quiet-hour invites; climbs to VIP.
6. **Review** — gets a post-meal check-in; happy → Google; unhappy → resolved privately.

## 13 · Technical Architecture (NAHALABS stack)

- **Framework:** Next.js App Router + TypeScript strict
- **UI:** Tailwind CSS + shadcn/ui
- **Auth:** Clerk (owners + super admin)
- **Database:** Neon PostgreSQL + Drizzle ORM (`drizzle-kit push`), `tenant_id` on every table
- **WhatsApp:** Evolution API — one instance per tenant; **Global key for lifecycle only, per-tenant token for sending** (never mixed)
- **AI:** Vercel AI SDK (concierge, sentiment, insights) — grounded, tools call services
- **Payments:** PayFast behind a typed client
- **Files:** Vercel Blob
- **Deploy:** Vercel; cron via Vercel Cron + GitHub Actions wake-up for Render/Evolution
